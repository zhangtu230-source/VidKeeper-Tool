## 为什么写这个工具

市面上的视频压缩工具几乎都有一个共同的痛点：**所有输出文件全部混到一个文件夹里**。

想象一下：你有两个文件夹，一个全是打球的视频，一个全是跳舞的视频。批量压缩后，它们全被丢进同一个输出目录 —— 你再也无法分清哪个是哪个。

本工具的核心设计原则正是解决这个问题：

> **输出永远在源文件目录下新建子文件夹，绝不混合。**

跨盘多路径输入 → 跨盘多路径输出，每个源文件夹独立产出自己的 `成功 / 失败` 子目录，**打球的归打球，跳舞的归跳舞**。

## 三大核心原则（来自 [新判定规则.txt](新判定规则.txt) 开头）

1. **能批量处理海量视频** —— 拖入即处理，无需一个个设置
2. **智能判断压缩比** —— 视频分辨率 / 帧率 / 编码 / 码率各不相同，由程序按规则表自动决策
3. **跨盘多路径输入，跨盘多路径输出** —— 输出在源文件目录新建子文件夹，避免混合（最重要）

## 功能特性

### 9 种处理模式

| 模式 | 名称 | 适用场景 |
|------|------|----------|
| 0 | 仅分析 | 不处理，只输出媒体信息报表 |
| 1 | 老片保画质 | 电视剧 / 纪录片 / 家庭录像归档，2× 阈值，CRF22 保守 |
| 2 | 老片省空间 | 模式1 的激进版，1.5× 阈值，CRF25 更省空间 |
| 3 | 小文件放行 | <100MB 现代格式直接放行，老格式走模式6 |
| 4 | 极速模式 | <100MB 直接放行，≥100MB 走模式1，最小化磁盘 I/O |
| 5 | 超高清压缩 | 4K / 2K / 1080p 专用，按分辨率固定 preset 与 tier |
| 6 | 老式格式转换 | 三步递进（Remux → Passthrough → Full Encode），兼容性优先 |
| 7 | 全部转 MP4 | 任意格式 → MP4，老式编码短路 Full Encode |
| 8 | 网络分发 | 1080p 生活视频分享，优先 x264 CRF20 |

### 智能决策能力

- **码率合理判定**：按分辨率查表（4K/2K/1080p/720p/480p/360p…）的均衡码率，结合 2× / 1.5× 倍率判定是否需要压缩
- **编码识别**：区分现代编码（H.264 / H.265 / AV1）与老式编码（MPEG-2 / ProRes / DV / WMV / RealVideo…）
- **容器判定**：MP4 / MKV / WebM 现代封装 vs 老式封装，MOV 按内部编码动态判定
- **HDR / 10bit 检测**：自动切换 x265 Main10 编码保留画质
- **反向压缩保护**：压缩后变大则丢弃新文件，源文件按原名移入成功目录
- **奇数分辨率修正**：自动向下取整为偶数以兼容 yuv420p
- **隔行扫描去隔行**：自动检测并启用 yadif

### GPU 加速（三档制）

| 模式 | 行为 |
|------|------|
| 关闭 | 强制 CPU（默认，质量优先） |
| 开启 | 强制 GPU（NVENC / AMF / QSV，失败即报错） |
| 智能判断 | 按规则自动决策（4K 硬性阻断、≥2K 鼓励启用、显存预估不足回退 CPU） |

### 帧率限制开关

- 默认关闭：保持源帧率
- 开启时：>30fps 强制降为 30fps（白名单 23.976 / 24 / 25 / 29.97 / 30 保持不变）
- 仅对重新编码有效，流拷贝不受影响
- 模式 0 / 3 / 4 自动变灰禁用

### 输出规则（v2.6 统一）

```
源文件目录/
├── 源文件.mp4                    （压缩/转换成功时保留原位置）
├── 模式名_成功/
│   ├── name_processed.mp4        ← 压缩成功（模式 1/2/5/8）
│   ├── name.mp4                  ← 格式转换成功（模式 6/7，不改名）
│   └── name.mp4                  ← 跳过 / 反压缩的源文件（原名）
└── 模式名_失败/
    └── name.mp4                  ← 失败的源文件（原名）
```

## 环境要求

- **操作系统**：Windows 10 / 11（macOS / Linux 理论支持，未充分测试）
- **Python**：3.9+
- **FFmpeg**：需安装并加入系统 PATH（[下载地址](https://ffmpeg.org/download.html)）

## 安装

### 方式一：直接运行 EXE（推荐普通用户）

从 [Releases](../../releases) 下载 `VideoCompressGPU.zip`，解压后运行 `VideoCompressGPU.exe`。

> 仍需自行安装 FFmpeg 并加入 PATH。

### 方式二：从源码运行

```bash
git clone <仓库地址>
cd 自制视频压缩

pip install -r requirements.txt

python main.py
```

## 打包 EXE

```bash
pyinstaller VideoCompressGPU.spec
```

产物位于 `dist/VideoCompressGPU/`。

## 完整规则文档

所有模式的判定逻辑、参数表、修订历史详见 [新判定规则.txt](新判定规则.txt)。

### v2.7 主要更新

- **模式5 参数调优**：1080p / 2K 从 CRF22 + 浮动 preset 改为 CRF21 + 固定 medium；4K 改为 CRF20 + fast；4K GPU tier 从 high (CQ21) 改为 lossless (CQ19)，使 GPU 画质与 CPU CRF20 对齐
- **模式8 preset 优化**：高码率视频（>4× 压缩比）的 preset 从 fast 提升为 medium，同 CRF 下文件更小 5-10% 且画质更好，利于网络分发
