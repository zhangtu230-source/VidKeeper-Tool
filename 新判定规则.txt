（影视/生活归档专用版 v2.7 Final）

零、模式功能总览

🟢模式0：仅分析        不解码、不编码、不移动，仅输出媒体信息报表
🟢模式1：老片保画质    电视剧/纪录片/家庭录像归档，2×阈值才压缩，CRF22保守
🟢模式2：老片省空间    模式1的激进版，1.5×阈值即压缩，CRF25更省空间
🟢模式3：小文件放行    <100MB现代格式直接放行，老式格式走模式6，≥100MB走模式1
🟢模式4：极速模式      <100MB直接放行，≥100MB走模式1，最小化磁盘I/O
🟢模式5：超高清压缩    4K/2K/1080p专用，1080p/2K=CRF21+medium，4K=CRF20+fast，老式编码转交模式6
🟢模式6：老式格式转换  三步递进（Remux→Passthrough→Full Encode），兼容性优先
🟢模式7：全部转MP4     任意格式→MP4，已是MP4+现代编码直接移动，老式编码短路Full Encode
🟢模式8：网络分发      1080p生活视频分享，优先x264 CRF20，HDR用x265 CRF22

模式间关系：
  模式2 = 模式1的激进版（更低阈值 + 更高CRF）
  模式3 = 小文件放行 + 模式1（≥100MB时）
  模式4 = 小文件放行 + 模式1（≥100MB时）
  模式7 = 模式6的MP4强制版（目标容器始终MP4）
  模式8 = 模式1的变体（x264优先 + 分辨率限制≤1080p）

一、全局基础规则（所有模式强制统一）

编码质量参数（影视优化标定）
编码类型   视觉无损   高质量(默认)   均衡   高压缩   ≤360p特别值
CPU x264   CRF 18   CRF 20   CRF 23   CRF 26   CRF 19（防块效应）

CPU x265   CRF 20   CRF 22   CRF 25   CRF 28   CRF 21（防块效应）

NVENC H.264   CQ 17   CQ 19   CQ 21   CQ 24   CQ 20（防块效应）

NVENC HEVC   CQ 19   CQ 21   CQ 23   CQ 26   CQ 22（防块效应）

⚠️ GPU 编码须知：
同等参数下，GPU 体积比 CPU 大 10%~30%，细节略逊，仅推荐用于大文件加速场景。

GPU 使用策略（三档制 · 影视场景优化）
模式   行为
off   强制 CPU（默认推荐，质量优先）

on   强制 GPU（失败即报错，仅大文件加速用）

auto   智能判断（规则如下）

✅ auto 智能判断逻辑（优先级从高到低）：

硬性阻断（满足任一即禁用 GPU）
    显存预估不足（4K / 大码率场景）
    编码器不支持当前格式
    源为 RGB / 非 yuv420p 像素格式
鼓励启用（满足任一即倾向 GPU）
    分辨率 ≥ 2K
    文件大小 > 4GB 且封装/编码属于"老式/特殊格式"白名单
默认回退
    不满足上述条件 → 使用 CPU

工业级安全兜底规则
规则项   强制执行逻辑
奇数分辨率   自动向下取整为偶数（兼容 yuv420p）

压缩后变大   丢弃新文件，源文件移动到成功文件夹（原名），记录日志

GPU 编码失败   自动切换为 CPU 同参数重试一次

致命错误   删除残余输出文件，原文件移动到 Fail 目录

帧率限制   由"帧率限制"开关控制（默认关闭）
           开启时：> 30fps 强制降为 30fps（白名单 23.976/24/25/29.97/30 保持不变）
           关闭时：保持源帧率不变
           仅对重新编码（compress_video / reencode_video）有效
           流拷贝（Remux / Passthrough）不受影响

VFR 处理   保持源 VFR 特性，不强行转 CFR

低分辨率保护   ≤360p 现代编码优先跳过，禁止自动降分辨率（含 360p → 240p / 144p）

音频保护   360p及以下音频码率 ≤ 64k AAC，不保留高码率音频

未知编码   仅当码率 > 2×均衡值时重编码，否则跳过；若编码无法被 ffmpeg 识别，直接移入 Fail 目录

帧率规则说明

由 GUI "帧率限制"复选框控制（默认关闭）：
  关闭时 → 保持源帧率不变（所有压缩操作均不降帧）
  开启时 → 按以下规则：
    合法帧率白名单：23.976 / 24 / 25 / 29.97 / 30 fps
    源帧率 ∈ 白名单 → 保持原样
    源帧率 > 30fps → 强制限制为 30fps
    源帧率 ∉ 白名单 且 < 30fps（如 20fps、15fps）→ 保持原样（不强制提升）

作用范围：
  ✅ 受控（GUI 帧率限制复选框可勾选）：模式1/2/5/6/7/8
      - compress_video：模式1/2/5/8
      - reencode_video：模式6第3步 / 模式7短路 Full Encode
  ❌ 不受控（GUI 帧率限制复选框变灰禁用）：模式0/3/4
      - 模式0：仅分析，不处理
      - 模式3/4：小文件放行（<100MB不压缩），流拷贝不改帧率
  ✖ Remux / Passthrough（模式6第1-2步）：流拷贝不改帧率，始终保持源帧率

"码率合理"定义

本文档中所有"码率合理"均指：
现代编码（H.264 / H.265 / AV1）且码率 ≤ 对应分辨率均衡值 × 对应倍率

≤360p 现代编码码率 ≤ 1.5× 均衡值 → 强制跳过（重编码收益为负）

全局音频策略（所有模式统一引用）
场景   处理方式
无音频流   不添加音频轨道

单音轨 / 立体声   AAC 128k（≤360p 用 64k）

多声道(5.1 / 7.1) · 目标容器 MP4   AAC 256k

多声道(5.1 / 7.1) · 目标容器 MKV / WebM   Opus 192k

音轨选择   保留所有音轨，不合并、不删除

≤360p 优化   强制音频 ≤ 64k AAC，避免浪费空间

⚠️ 强制规则：所有模式中涉及音频转码的步骤，均引用本表，不得单独指定与目标容器矛盾的音频参数。

二、统一输出规则（v2.6 新增）

所有模式的输出统一遵循以下规则：

输出目录结构
  源文件目录/
  ├── 源文件.mp4（处理后保留原位置，仅压缩/转换成功时）
  ├── 模式名_成功/
  │   ├── name_processed.mp4    ← 压缩成功（模式1/2/5/8）
  │   ├── name.mp4               ← 格式转换成功（模式6/7，不改名）
  │   └── name.mp4               ← 跳过/反压缩的源文件（原名移动至此）
  └── 模式名_失败/
      └── name.mp4               ← 失败的源文件（原名移动至此）

各类处理结果的输出规则：
情况              源文件处理                        新文件命名
跳过(决策skip)    移动到_成功文件夹(原名)            无新文件
反向压缩          移动到_成功文件夹(原名)            新文件已删除
压缩成功(1/2/5/8) 保留原位置不动                    name_processed.mp4 在_成功文件夹
格式转换成功(6/7) 保留原位置不动                    name.ext(原名)在_成功文件夹
失败              移动到_失败文件夹(原名)            残余文件已删除
未知编码          移动到_失败文件夹(原名)            —

⚠️ 残余文件清理：所有失败路径必须先删除损坏的输出文件（os.remove），再移动源文件到失败文件夹。

四、格式白名单定义

现代封装 / 编码（无需兼容性转封装）

MP4, MKV, WebM, AV1, HEVC(H.265), H.264

⚠️ MOV 容器特别说明：
MOV 容器虽为现代封装，但内部可能包含老式编码（ProRes / DV / MPEG-2 等）。
判定逻辑：先检测视频编码，再检测容器。
MOV + H.264/H.265/AV1 → 视为现代格式
MOV + ProRes/DV/MPEG-2/其他老式编码 → 视为老式格式，需兼容性处理

老式 / 特殊格式（需兼容性处理）

.m2ts, .mts, .vob, .m2v, .ts, .tp        // 广电 / 光盘格式
.mxf, .gxf, .lxf                          // 专业摄像格式
.rm, .rmvb, .wmv, .avi, .flv, .swf        // 互联网早期格式
.mpg, .mpeg, .mod, .tod                    // 老相机 / 磁带格式
.3gp, .3g2, .asf, .ogv                    // 移动设备早期格式
MOV + 老式编码（ProRes / DV / MPEG-2）     // 专业设备老编码

老式 / 特殊编码（不论容器）

MPEG-1, MPEG-2, ProRes, DV, Cinepak, Sorenson, WMV1/2/3,
RealVideo, Theora, Flash Video (VP6/Sorenson Spark), MJPEG

④   现代编码且码率合理（≤ 2×均衡值）   跳过

模式2：老片省空间（模式1的激进版）
适用：2010年前老剧、DVD转录、低分辨率老视频
特点：1.5×均衡值即触发压缩（比模式1更积极），CRF25更省空间
与模式1的梯度差异：
  触发阈值更低：1.5×均衡值即压缩（模式1为2×）
  压缩参数更激进：CRF25（模式1为CRF22）
判定逻辑（严格按优先级顺序执行，命中即停）：
优先级   条件   行为
①   码率 < 300kbps   跳过（再压无意义）

②   ≤360p 且现代编码   强制跳过

③   ≤360p 且老式编码   仅转封装（Stream Copy），不重编码视频流

④   >360p 且老式编码   压缩（CPU x265 CRF25）

⑤   >360p 且现代编码 且码率 ≤ 1.5×均衡值   跳过

⑥   >360p 且现代编码 且码率 > 1.5×均衡值   压缩（CPU x265 CRF25）

模式5：超高清压缩（4K / 2K / 1080p）
适用：4K电影、高端相机 / 无人机素材、高码率1080p
特点：4K默认不压，老式编码转交模式6，2×阈值判定
v2.7参数调优：1080p/2K=CRF21+medium，4K=CRF20+fast(GPU: CQ19 lossless)
判定逻辑（严格按优先级顺序执行，命中即停）：
优先级   条件   行为
①   老式编码 / 老式容器   转交模式6处理（兼容性优先，不直接 HEVC 压缩）

②   ≤ 720p（含 360p 及以下）   跳过

③   1080p 且码率 > 2× 均衡值（> 10 Mbps）   压缩（x265 CRF21 + preset=medium，GPU tier=high CQ21）

④   1080p 且码率 ≤ 2× 均衡值   跳过

⑤   2K 且码率 > 2× 均衡值（> 20 Mbps）   压缩（x265 CRF21 + preset=medium，GPU tier=high CQ21）

⑥   2K 且码率 ≤ 2× 均衡值   跳过

⑦   4K 且码率 > 3× 均衡值（> 48 Mbps）且 --4k-compress=true   压缩（x265 CRF20 + preset=fast，GPU tier=lossless CQ19，保持 4K）

⑧   4K（其余情况）   跳过

--4k-compress 参数定义（v2.5 新增）：
属性   值
CLI 参数   --4k-compress

配置文件键   compress_4k

类型   Boolean

默认值   false（跳过所有 4K）

设为 true 时   仅对码率 > 48 Mbps 的 4K 文件执行压缩

示例   vtool --mode 5 --4k-compress ./input/

⚠️ 警告：4K 转码极度耗时，优先保留源文件
核心原则：4K 不降分辨率，不主动压缩；老式编码走兼容性路径而非直接 HEVC

模式6：老式格式转现代封装（兼容性优先）
适用：电视盒子、老播放器兼容
≤360p 优化：仅执行第1-2步，不重编码视频流

目标容器选择规则：
  源视频编码为 H.264 / H.265 / AV1 → 目标容器 MP4
  源视频编码为 MPEG-2 / 其他老式编码 → 目标容器 MKV（兼容性更好）
  第3步 Full Encode 后编码为 H.264 → 目标容器 MP4

处理逻辑（三步递进，成功即停）：
步骤   操作   音频处理   说明
Remux   容器转换，音视频流直接拷贝（Stream Copy）   不转码   目标容器按上方规则选择

Video Passthrough   视频流拷贝，音频转码   按全局音频策略执行：MP4→AAC 128k/256k；MKV→AAC 128k / Opus 192k   解决音频编码不兼容

Full Encode   视频 CPU x264 CRF20   按全局音频策略执行   完全兜底

反向压缩检测：
  Full Encode 后变大 → 丢弃新文件，源文件移动到成功文件夹（原名）
  Remux/Passthrough 后明显变大(>20%) → 丢弃新文件，源文件移动到成功文件夹（原名）

≤360p 兜底规则：
  > 若第1-2步均失败（如 MPEG-2 + MP4 不兼容），允许执行第3步 Full Encode，
  > 但使用 ≤360p 特别 CRF 值（x264 CRF19 / x265 CRF21），防止块效应。
  > 若第3步仍失败 → 删除残余文件，原文件移入 Fail 目录。

模式7：全部转为 MP4
逻辑：
  已是 MP4 且内部编码为现代编码（H.264 / H.265 / AV1）→ 移动到成功文件夹（原名）
  已是 MP4 但内部编码为老式编码（MPEG-2 等）→ 直接执行模式6第3步 Full Encode → MP4（短路优化，避免无效 Remux）
  其他格式 → 执行模式6的三步处理逻辑（目标容器强制 MP4；若源编码为 MPEG-2 等 MP4 不兼容编码，跳过第1-2步，直接执行第3步 → MP4）

输出命名：转换后文件不改名（name.mp4），成功和失败各有单独文件夹

模式8：网络分发（1080p 生活视频分享）
适用：家庭群分享、社交平台上传
特点：优先x264 CRF20（兼容性好），HDR用x265 CRF22
分辨率限制：
  > 本模式仅面向 1080p 及以下生活视频。
  > ≥ 2K（含 4K）→ 跳过（不适用本模式，请使用模式5）

基础逻辑：同模式1 优先级判定表，但压缩参数覆盖为：
  优先：CPU x264 CRF20（High Profile @ Level 4.1）
  HDR / 10bit 源：CPU x265 CRF22（Main10 @ Level 5.0）
  v2.7 preset：高码率视频(>4×压缩比)从fast提升为medium，保质量+利于网络传输

帧率限制：由全局"帧率限制"开关控制（默认关闭）
  开关关闭：保持源帧率不变
  开关开启：> 30fps → 限制为 30fps，≤ 30fps → 保持原样

音频策略：按全局音频策略执行

v2.7（模式5参数调优 + 模式8 preset优化版）

🟡 逻辑完善（2项）
模式5参数调优：1080p/2K从CRF22+浮动preset改为CRF21+固定medium（画质提升约15-20%，文件仅+5-8%）；4K从CRF22+浮动preset改为CRF20+固定fast（保细节+保速度）；4K GPU tier从high(CQ21)改为lossless(CQ19)，使GPU画质与CPU CRF20大致对齐。preset不再浮动，按分辨率固定。
模式8 preset优化：高码率视频(>4×压缩比)的preset从fast提升为medium，同CRF下文件更小5-10%、画质更好，利于网络传输；GPU回退CPU路径同步应用。

v2.6 Final（影视/生活归档专用 · 输出规则统一 + 帧率开关版）
